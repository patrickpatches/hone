The pantry as supply vs demand

Patrick asked: a tomato in one recipe, then a second recipe also wants a tomato — it should say 2. The good news: that adding-up already exists in the shopping engine. This redesign organises the pantry by category with clean line icons, keeps the search-first add bar, and surfaces the smart, recipe-driven quantity that's already being calculated.

One ingredient, three numbers — and you only ever touch one of them.
Need summed from the recipes you've planned — automatic
Have one tap: "I've got this" — the only thing you maintain
Buy Need minus Have → flows to your shopping list

No typing quantities. The numbers come from your recipes, so the pantry can't go stale — that's the trap most quantity-tracking apps fall into.

How the "smart quantity" works

Your exact example, on screen

Tomato → 2, automatically

Each ingredient row remembers which recipes asked for it. Add another recipe that needs the same thing and the count climbs — no editing, no double entry.

Plan: Bolognese
Tomato 1 from Bolognese need 1
＋ add Shakshuka ↓
Plan: + Shakshuka
Tomato 1 from Bolognese + 1 from Shakshuka need 2
This logic already exists. The shopping engine (shopping-helpers.ts) already tracks every ingredient's source recipes and re-sums the quantity on each meal add/remove. We're not building the maths — we're showing it in the pantry, and tagging the source ("from Bolognese + Shakshuka") from data that's already there. Engineer cost: mostly UI — group the existing items by category, draw the icons, render the source line. The new bit is letting the pantry "have" tick subtract from the buy quantity. Roughly a session, no new data model.

Where amounts can — and can't — add up

Honesty rule: Hone never fakes a unit conversion. Same unit → it sums. Different units → it stays split and tells you, rather than inventing "1.7 of something".

whole 1 tomato + 1 tomato = 2 tomatoes ✓
weight 200 g + 300 g flour = 500 g ✓
mixed 1 tin + 200 g tomato kept split ⚠

The "kept split" case shows two short lines under one ingredient ("1 tin · 200 g") — honest, and matches the existing engine's behaviour, which already refuses grams↔cups conversions.
